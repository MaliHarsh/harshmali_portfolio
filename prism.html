01 / The challenge

Find the research
you don’t know to search for.

HackPSU’s Research Track asked us to make scientific research faster by removing an avoidable delay. We focused on literature discovery: relevant papers may describe the same subject in different languages, yet a researcher’s initial query often reaches only part of that evidence.

A translation tool can help someone read a paper they have already found. Our question was earlier in the workflow: how do we help them discover that paper at all? A query about drought stress in rice, for example, should have a path to research using Chinese or Spanish terminology as well as English.

As an undergraduate researcher, I see the value of being able to trace an answer back to a paper. Prism brings that priority into a software product: broader discovery, visible sources, and an honest account of what the available metadata can tell us.

Our goal

Let researchers ask one question in their own language, explore relevant papers across languages, and follow every result back to its source.

02 / The product

Search broadly.
Inspect the evidence.

Prism expands a research question into queries in 18 languages and retrieves live records from OpenAlex. It ranks the candidates together using semantic similarity and keyword matching, rather than requiring every paper to contain the exact words in the original query.

Discover

Compare Hybrid, Semantic, and Keyword rankings. Filter by publication language and year, inspect why a result matched, and save papers to a browser-based reading list.

Understand

Read original titles and abstracts alongside clearly labeled machine translations. Optional summaries stay within the information available in the abstract.

Compare

The Gaps view compares themes in samples of papers from different languages, linking the counts and findings back to the papers behind them.

Explore

A publication-country map provides another way to navigate results. It uses the venue’s recorded country, rather than claiming to locate the study or its authors.

The 18 supported query languages

English, Chinese, Spanish, Portuguese, French, German, Japanese, Russian, Korean, Indonesian, Italian, Turkish, Polish, Ukrainian, Arabic, Hindi, Afrikaans, and Swahili.

03 / How we built it

A search pipeline
with visible reasoning.

01 / EXPANDOne question

Gemini generates research queries across languages.

02 / RETRIEVELive records

OpenAlex returns candidate papers and metadata.

03 / RANKShared relevance

Multilingual embeddings combine with BM25.

04 / EXPLAINTraceable results

Show match evidence, sources, and language coverage.

The frontend uses Next.js 16, React 19, TypeScript, Tailwind CSS, and shadcn/ui. A three.js globe gives the landing page its visual identity. Node.js API routes coordinate retrieval and AI tasks, with deployment on Vercel.

For meaning-based ranking, Transformers.js runs paraphrase-multilingual-MiniLM-L12-v2 on the server. The query representation averages embeddings across its translations. The default hybrid score combines 70% semantic similarity with 30% BM25 keyword relevance; these are tunable design choices, not proven optimal weights.

Gemini handles bounded language tasks: rewriting queries, checking suspicious language tags, translating text, and identifying themes. Missing abstracts and other missing fields remain visible instead of being filled with invented content.

04 / Evidence-led AI

Let the model label.
Let code count.

The Gaps feature was one of the most important design lessons. An early prototype could produce a confident summary that contradicted its own counts, or include papers that matched a fragment of a word but missed the actual topic.

We redesigned the workflow to filter off-topic papers, identify themes supported by each paper’s text, and calculate the comparisons in code. The narrative summary is then generated from those computed findings. Each finding retains links to its supporting papers.

A research lead, not proof of a missing literature.

The default analysis samples up to 15 relevant papers per language. A theme absent from that sample may still exist elsewhere. Prism makes the comparison inspectable so a researcher can investigate further.

05 / Engineering decisions

The hard part was
making results trustworthy.

Problem we encounteredHow the team responded
Equal sampling distorted the language mixA Shakespeare query overrepresented smaller literatures. We allocated candidates in proportion to estimated topic coverage, then ranked by relevance.
Language metadata was sometimes wrongWe flagged disagreements between a record’s text and language tag for a Gemini check, while accounting for journals that supply English abstracts.
Hindi keyword matching failed silentlyWe normalized Devanagari text to account for vowel signs missing from indexed text, applying the same treatment to queries and records.
ML inference strained serverless deploymentThe team reduced the runtime package to the needed Linux binaries and loaded the embedding model on demand.
API budgets and rate limits interrupted searchesCaching reduced repeat work, and automatic Gemini model fallback helped handle unavailable or rate-limited models.

07 / Outcome & lessons

Build quickly.
Keep the evidence.

We shipped a live product with multilingual search, an inspectable ranking pipeline, publication mapping, and evidence-linked theme comparisons. Our hackathon submission reported 153 automated tests using Vitest and Playwright.

Fairness is an implementation decision.

Sampling, normalization, and missing metadata change whose research gets seen. Adding more languages is only the beginning; the ranking pipeline also has to avoid giving one language an accidental advantage.

AI works best with checkable responsibilities.

The Gaps redesign showed why narrow labeling tasks and deterministic calculations are easier to inspect than asking a model to produce an entire analysis at once.

Shipping exposes the real constraints.

Function size, cold starts, API budgets, and inconsistent data all shaped the finished product. The experience connected product design with the engineering work needed to make an idea usable.

Next steps include broader language coverage, larger and deeper theme comparisons, Zotero and BibTeX export, persistent caching, and evaluation with multilingual researchers. A formal benchmark is still needed to measure improvements over a single-language search.
